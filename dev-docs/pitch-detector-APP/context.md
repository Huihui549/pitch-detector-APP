# context.md — pitch-detector-APP

## 一句话

把网页版音高检测工具重写为跨平台 Qt 应用：手机 APP + 电脑桌面客户端，并为嵌入式设备预留接入点；服务于练琴/练唱时的音准自查。

## 上游关系

| 项 | 值 |
|---|---|
| 上游项目 | `[PC] <兄弟目录>/pitch-detector-web`（网页版，**只读**，1 个提交 `9cb3830`） |
| 上游算法真值 | `[上游] tools/pitch-engine.js`（UMD，浏览器 + Node 双环境） |
| 上游准确度基线 | 钢琴 88 键命中 **84/88（95.5%）**，命中键偏差中位 6.1 音分 |
| 上游素材 | **本机实际存在**（2026-09-30 复核）：`[上游] resource_audio/870f3-main/钢琴88键独立音频文件/`，88 个 WAV（9.0 s / 2ch / 16bit / 44.1 kHz），文件名即标准答案。注意：早期记录曾误判为"已缺失"（见坑 A9 已更正） |

## 分层与依赖方向（硬约束）

```
qml/  ──▶  src/app/  ──▶  src/io/  ──▶  src/core/
                └──────▶  src/audio/ ──▶  src/core/
```

- 依赖只允许**从左向右**；`src/core/` 不依赖任何其它层，也不依赖 Qt（仅标准库）
- `qml/` 禁止算法痕迹：阈值、τ、窗长、音名换算一律不得出现在 QML 中（R11：界面留调用、逻辑留 C++）

## 关键参数（**全部继承上游，改动必须重新实测并更新本表**）

| 参数 | 值 | 上游依据 |
|---|---|---|
| A4 基准 | 440 Hz（界面可改） | `pitch-engine.js` `A4` |
| 音名体系 | 科学音高记号，中央 C = C4 | 上游 spec 冻结项 |
| 音域（文件分析/全键盘） | 27–4300 Hz | 级联窗长支撑全 88 键 |
| 音域（实时链路） | 上游为 82–1050 Hz 固定窗 4096；**本项目首版沿用固定窗 4096**（ADR-0004，切换条件见该 ADR） | 上游 `pitch.html` 实时循环；QAudioSource 可用更长窗，但延迟须实测后再调 |
| 级联窗长 | `[1024, 2048, 4096, 8192, 16384]` | 全键盘周期跨度 152 倍，单窗两端必坏（pitfalls #19） |
| YIN 阈值 | 0.3 | 实测网格中唯一全局可用值 |
| RMS 静音门槛 | 绝对 `0.008` + 相对峰值 `0.02` | 高音键 0.2 s 内衰减到峰值 10% |
| 浅谷复核阈值 | 0.15（2 倍处需 < 当前谷一半且距全局最小 < 0.05） | 修钢琴 G3 的 +1208 音分误判 |
| τ 精修 | ±0.5 样点、步长 1/64，线性插值 | 抛物线只用三点，高音曲率偏差大 |
| 频域精修 | ≥500 Hz 启用，±3% 内 240 步 + 抛物线 | A#7 各窗长固定 +48 音分 |
| 谐波一致性复核 | `HARMONIC_MAX=8`、权重 `1/k`、分频下限 40 Hz、改判需分数 > 1.15 倍 | 八度摇摆主对策；几何平均已实测回退（pitfalls #29） |
| 八度轨迹校正 | 参考 = 置信度加权中位数，整数倍容差 ±120 音分，折 ±1200/±2400 | C2 的 863 帧由「473 C2 + 388 C3」变 861 C2 |
| 帧进（文件分析） | 441 样点 = 10 ms | 精度优先，允许非实时 |
| 帧进（实时） | 上游 512 样点 = 11.6 ms | **本项目按 QAudioSource 缓冲重定**，需实测端到端延迟 |
| 读数保持 | 700 ms（防闪断） | 上游实时页 |
| 极值更新条件 | 置信度达标 + 连续命中 ≥3 帧 | pitfalls #4 |
| 判定口径 | 音名正确 **且** 偏差 < 50 音分（双条件） | 只查音名会被"标签对、频率差一个八度"蒙混（pitfalls #26） |
| 聚合口径 | 众数音名；参考频率用置信度加权中位数 | pitfalls #27 |

## 硬性约束（违反即失败）

- [ ] `src/core/` 不依赖 Qt、不依赖 UI（**已实测 PASS**：零 `#include <Q`）
- [ ] `qml/` 内无任何算法与阈值
- [ ] 编译 0 warning
- [ ] 算法参数与上游逐项一致，差异必须写入 ADR 并附实测数据
- [ ] 同一输入下 C++ 与 JS 引擎输出一致（逐帧 float64 比对 + 逐帧音名一致，见 `verify.md` B 组）
- [ ] 不做多音高、不做评分、不引入第三方音频/DSP 库（YIN 自实现）
- [ ] 测试素材缺失时必须 FAIL，不得静默跳过（坑 A7/A9）
